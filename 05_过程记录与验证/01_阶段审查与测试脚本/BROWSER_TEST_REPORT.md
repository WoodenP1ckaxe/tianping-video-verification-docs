# 浏览器联调报告

> 历史说明：本文件记录修复前构建的联调过程。其中“无卡面仍自动生成记录并完成流程”的第 4～8 步依赖已废弃的登录账号/OCR 标定值回退，不能作为当前版本的验收证据。当前版本的真实样例会因没有可解码卡面而进入“待人工处理”；最新功能与浏览器结果见 `重要需求修复核验_20261101.md`。

## 环境

- 日期：2026-11-01
- 浏览器：Microsoft Edge（Playwright 驱动，无头模式）
- 服务：Node.js 24，独立临时数据目录
- 检查方式：DOM、网络响应和页面异常；未批量截取或审阅图片

## 已执行

1. 登录页正常渲染，首次登录触发强制改密。
2. 检验人员可进入工作台、任务、记录和导出页面，记录数据来自后端。
3. 桌面四主路由均渲染，移动端 390×844 视口横向溢出为 0。
4. 浏览器真实选择客户 MP4，填写并确认拍摄时间，执行三个 8 MiB 分片上传。
5. 上传任务进入 FIFO 队列并完成，生成关联记录、九次示数和截图。
6. 通过记录路由直接打开刚生成的记录时，前端可补拉详情并显示九次读数。
7. 检验人员将低置信读数标记核对、修订低置信口述项后成功一键提交。
8. 复核确认人员完成电子签名，记录状态锁定为“已复核确认”。
9. 管理员成功加载主数据、模板、账号、审计和运行状态五个页面。
10. 页面脚本异常为 0；无资源请求失败；登录前预期的一次
    `GET /api/session` 401 不计为故障。
11. 点击读数截图可打开“识别帧核验”，真实视频帧上有黄色显示屏识别框，
    同屏显示帧偏移、帧内识别文本、记录换算值、测量时间、置信度和稳定状态。

## 联调中发现并修复

- 上传完成后任务先于业务状态快照刷新时，点击新记录曾出现“未找到记录”。
  已增加按记录 ID 的服务端详情补拉，并在任务完成且本地缺少记录时刷新完整状态。
- 浏览器 favicon 缺失造成 404，已加入本地 SVG 图标。
- 前端残留固定默认口令文案，已改为部署配置/随机一次性口令语义。
- 原样例清单偏移对应到清零或过渡画面，识别值与截图不一致。现已按真实样例
  校正九次读数偏移与数值，增加帧内文本/记录值一致性校验，并重新校准当前
  待提交样例记录的九张截图。
- 分析器已改为逐秒读取真实视频帧。七段码用本地模板 OCR，彩色显示区用离线
  Tesseract 回退，不再按视频 SHA-256 读取预置读数。
