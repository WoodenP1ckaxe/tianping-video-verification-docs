# 后端安全与业务完整性审查报告

审查日期：2026-10-26  
审查范围：`server.js`、`src/auth.js`、`src/db.js`、`src/api.js`、
`src/services/uploads.js`、`src/services/queue.js`、`src/services/storage.js`、
`src/services/analyzer.js`、导出实现与现有自动化测试。  
审查方式：代码审阅 + 独立临时数据库 API 复现 + 全量测试。

## 结论

基础安全设计总体可用：口令使用加盐 scrypt 存储，服务端会话与 CSRF 校验生效，
停用账号不可登录，连续错误口令会锁定账号，越权接口和跨账号记录修改被拒绝，
审计日志由数据库触发器禁止更新和删除。真实样例的上传、分析、提交、复核和 PDF
导出流程通过测试。

当前不建议直接按默认参数上线。默认初始口令、上传临时空间无上限、可伪造审计来源
三个问题需要部署前处理；审计覆盖、CSV 注入、内部路径泄露和输入长度限制应在正式
交付前加固。未发现可绕过身份认证直接读取数据库或修改业务数据的远程漏洞。

## 风险汇总

| 级别 | 问题 | 影响 | 建议优先级 |
| --- | --- | --- | --- |
| 高（条件性） | 已知默认初始口令 | 若未设置 `INITIAL_PASSWORD`，内网人员可在首次改密前抢占管理员账号 | 发布前必须 |
| 高 | 上传会话和临时文件无总量限制、无过期清理 | 已登录检验人员可持续创建会话或上传未完成文件，耗尽磁盘/inode，使 Web、数据库和队列不可用 | 发布前必须 |
| 中 | 无条件信任 `X-Forwarded-For` | 客户端可伪造审计来源 IP，削弱追溯证据可信度 | 发布前必须 |
| 中 | 查询、详情和视频查看未写审计 | 不满足 FR-1008“查询与导出操作应写入审计日志”的合规要求 | 发布前必须 |
| 中 | 关键状态更新与审计写入不在同一事务 | 审计写入失败时可能出现业务已变更但无对应审计，破坏原子追溯 | 发布前必须 |
| 中 | CSV 未防公式注入 | 经 Excel 打开导出文件时可执行以 `= + - @` 开头的单元格公式 | 发布前应修复 |
| 中 | 普通角色可获服务器绝对文件路径 | 泄露主机目录、临时目录和部署结构，便于进一步攻击 | 发布前应修复 |
| 中 | 备注/修改理由缺少业务长度上限 | 单个已认证用户可以写入接近 2 MiB 的文本并反复追加，造成数据库和导出膨胀 | 发布前应修复 |
| 低 | 视频流读取缺少错误处理 | 文件恰在 `stat` 后被清理或替换时，ReadStream 错误可能成为未处理异常 | 应修复 |
| 低 | 极端有限数值舍入后可能变为 `Infinity`，落库变 `null` | 修正动作审计值与最终数据不一致，判定原因误导 | 应修复 |
| 低 | 分析完成后先移动视频，再提交数据库事务 | 进程在两步之间退出会留下无法重试的丢失文件状态 | 应修复 |
| 低 | 非管理员 `/api/state` 返回全部账号状态 | 暴露停用账号等非必要信息，违反最小信息披露原则 | 建议修复 |
| 低 | `/api/health` 分支顺序错误 | 第二个公开健康分支永远不可达，接口行为与代码意图不一致 | 建议修复 |

## 详细问题与证据

### R-01 已知默认初始口令

**级别：高（条件性发布阻断）**

`server.js:41`、`src/db.js` 初始化逻辑和 `docker-compose.yml:19` 使用固定默认口令
`Tp123456`。文档虽提示生产部署前修改，但程序不会拒绝使用默认值启动。

首次登录强制改密只能降低长期风险，不能消除初始化窗口内的账号抢占风险。所有初始
账号共享该口令，攻击者若能访问内网页面，可先登录管理账号并修改口令。

建议：

- 新数据库初始化时若未显式设置 `INITIAL_PASSWORD`，生成一次性随机口令并仅输出到
  本机标准输出/初始化文件。
- Compose 使用 `${INITIAL_PASSWORD:?必须设置}`，禁止静默默认值。
- 启动日志和文档明确提示首次部署后立即使全部初始账号完成改密。

### R-02 上传配额可由未完成会话绕过

**级别：高（可用性/存储）**

`src/services/uploads.js:66-116` 的 `initialize` 只校验单个文件上限，没有检查同一
用户的进行中上传数量、全局上传数、临时空间总量或磁盘余量；仓库中也未发现对
`uploads` 表和 `.part` 文件的 TTL 清理。`src/services/storage.js` 的视频配额只统计
`videos/`，不统计尚未完成的上传。

隔离环境实测连续创建 25 个 1 字节声明大小的上传会话，25 个全部成功，磁盘上对应
目录全部保留。攻击者可将 `sizeBytes` 声明为接近 500 MiB 并通过分片实际填满磁盘。
配额达到上限的自动清理对所有账号同时造成可用性影响。

建议：

- 配置每用户/全局进行中上传数量上限和上传临时空间上限。
- 初始化时检查磁盘剩余空间、配额余量和用户已有 `receivedBytes`。
- 启动时和周期任务清理超过配置 TTL、未继续上传的 `.part` 文件及会话，并写审计。
- 视频配额统计同时纳入上传临时文件，或在总数据盘上设置高于视频配额的硬保护线。
- 自动清理必须排除当前 `分析中` 任务的视频。

### R-03 审计来源 IP 可伪造

**级别：中（审计完整性）**

`src/auth.js:82-85` 无条件采用请求头 `X-Forwarded-For` 的第一个值作为客户端
IP，且所有审计都使用该值。

隔离环境以请求头 `X-Forwarded-For: 203.0.113.77` 登录 U002，管理员审计接口记录
的来源 IP 即为 `203.0.113.77`。直接访问服务时，该地址并非真实连接地址。

建议：

- 默认使用 `req.socket.remoteAddress`。
- 仅配置了可信反向代理 CIDR/地址时解析转发头，并遍历可信代理链取最右端可信值。
- 审计中可分别记录真实 socket 地址和代理来源，禁止用户头覆盖真实地址。

### R-04 查询类操作未审计

**级别：中（合规/追溯）**

`src/api.js:551-568` 的记录查询、`:657-680` 的记录详情、`:530-568` 的视频与截图读取
均只做权限校验，没有写“记录查询/证据查看”审计。

隔离环境实测管理员在查询前后审计总数均为 19；查询记录列表和详情后没有新增审计
事件。FR-1008 明确要求查询与导出操作写入审计日志。

建议：

- 对列表查询记录筛选条件和返回条数。
- 对详情、视频、截图读取记录对象 ID；高频逐张截图读取可采用一次会话语义聚合，
  但仍应保证可追溯。
- 对拒绝的查询也记录 403 访问拒绝，当前错误处理只覆盖带已认证会话的 403。

### R-05 业务状态与审计不是原子事务

**级别：中（可审计性）**

多处业务更新和审计写入是两次独立数据库操作，例如：

- `src/api.js:1230-1247` 提交记录后单独写审计；
- `src/api.js:1250-1274` 复核确认后单独写审计；
- `src/api.js:1302-1325` 作废后单独写审计；
- `src/api.js:1519-1570` 账号修改/删除和审计分开；
- `src/services/uploads.js:242-278` 任务创建提交后才写上传完成审计。

如果磁盘满、数据库触发约束或进程退出，业务数据可能已更新而审计未写入。审计日志
本身的 UPDATE/DELETE 触发器不能解决“缺少 INSERT”的问题。

建议：

- 同一业务状态变更、字段留痕和审计 INSERT 放入同一 SQLite 事务。
- 文件移动/删除等无法与 SQLite 同事务的操作采用持久化 outbox/补偿日志记录，
  启动时自动校验并补写。

### R-06 CSV 公式注入

**级别：中（客户端代码执行风险）**

`src/api.js:1837-1846` 与 `src/services/exporter.js:943-946` 只做 CSV 引号转义，
没有处理以 `= + - @`、制表符或回车开头的危险单元格。

隔离环境将 F001 备注设为
`=HYPERLINK("http://evil.invalid","audit")`，导出 `type=devices` 后该值原样进入 CSV
备注列。使用 Excel 打开时，引用不会消除公式解释。

建议：对所有字符串单元格在去掉前导控制字符后检测危险首字符，前置单引号 `'`，
并增加针对 `= / + / - / @ / TAB / CR` 的回归测试。不要仅依赖整体加引号。

### R-07 内部绝对路径泄露

**级别：中（信息泄露）**

`src/db.js:1007` 将 `file_path` 映射为 DTO 的 `filePath`，`src/api.js:873-880`
又把该 DTO 放入 `/api/state` 的任务集合；`/api/records/:id` 也附带任务对象。

隔离环境以复核确认人员身份请求 `/api/tasks?scope=all`，成功得到：
`C:\Users\...\Temp\tianping-security-audit-20261026\videos\...\T-...mp4`。
复核人员只需要任务状态，不需要服务端绝对路径。

建议：

- 对外 DTO 删除 `filePath`、临时路径和主机路径。
- 内部路径仅由受限服务读取；需要下载时使用记录/任务 ID 解析。
- 增加 DTO 白名单测试，防止新增数据库字段意外暴露。

### R-08 文本与修改理由缺少业务长度上限

**级别：中（资源消耗/数据质量）**

`src/api.js:1120-1181` 对备注、修改理由没有长度限制，只受 2 MiB JSON 请求体上限
约束；`updateReadout` 和 `checkField` 的理由同样未截断。

隔离环境写入 524,288 个字符的备注被接受（HTTP 200），响应约 1 MiB。已提交但未
复核记录可反复修改备注，每次修改均累积到 `modifications_json` 和审计日志。

建议：

- 备注建议限制 2,000 字符；修改/核对理由建议 1,000 字符。
- 服务端按 Unicode 字符或 UTF-8 字节定义上限，并返回明确 400 错误。
- 列表/状态接口避免返回完整修改历史，详情接口分页获取。

### R-09 流式文件错误未接管

**级别：低（可用性）**

`src/api.js:231-270` 和 `server.js:148` 在 `existsSync/statSync` 后直接用
`createReadStream(...).pipe(res)`，未绑定 ReadStream 的 `error`。容量清理、外部文件
删除或存储故障发生在两步之间时可能产生未处理异常。

建议使用 `stream.pipeline()` 并对错误做响应头状态判断，保证单个文件读取错误只终止
当前响应，不终止 Node 进程。

### R-10 极端读数舍入导致数据不一致

**级别：低（数据质量）**

`src/api.js:1035-1061` 先确认输入为有限数，再乘放大系数并舍入，但没有检查舍入结果。
隔离环境向 I1-1 提交 `1e308`，接口返回的读数为缺失，而审计仍描述修改为极大值；
JSON 序列化把非有限数变成 `null`。

建议在舍入后用 `Number.isFinite` 再次校验，并给读数设置与天平量程相关的合理上限。

### R-11 队列文件移动与数据库提交之间有崩溃窗口

**级别：低（可靠性/一致性）**

`src/services/queue.js:324` 先移走视频，`:334` 之后才在事务中插入记录并更新任务。
若进程在之间退出，任务仍为 `分析中`，重启后任务变失败，但 DB 中的旧 `file_path`
已失效，重试无法找到文件。

建议：

- 在事务前记录目标路径/迁移意图；事务提交后再移动，提供启动核对；
- 或先把文件复制到目标并校验，再提交 DB，成功后再删除源文件；
- 启动恢复时根据任务 ID、记录 ID和两个候选路径执行幂等修复。

### R-12 非管理员状态快照暴露非必要账号信息

**级别：低（最小披露）**

`src/api.js:873-893` 向所有已登录角色返回全部账号；对非管理员仅移除失败次数和锁定
时间，仍包含所有账号 ID、姓名、角色、状态、首次改密标记和最近登录。

若界面只需显示检验人员姓名，应返回去标识化的姓名映射，不返回账号管理数据。

### R-13 `/api/health` 分支不可达

**级别：低（正确性）**

`src/api.js:382` 的第一个健康检查同时匹配 `/healthz` 和 `/api/health` 并立即返回；
`:401` 的第二个 `/api/health` 分支永远无法执行。当前不会泄露密码，但应删除重复
分支或按注释改为仅 `/healthz` 公开。

## 已验证的安全控制

以下项目在代码审阅和隔离 API 测试中通过：

| 控制 | 证据/结果 |
| --- | --- |
| 口令存储 | `src/db.js:97-112` 使用随机 salt + scrypt + `timingSafeEqual` |
| 登录失败锁定 | U002 连续 4 次错误返回 401，第 5 次返回 429；锁定期正确口令仍返回 429 |
| 首次登录强制改密 | 未改密时 `/api/state` 返回 403 `PASSWORD_CHANGE_REQUIRED` |
| CSRF | 无 `X-CSRF-Token` 的登出请求返回 403 `CSRF_INVALID` |
| 停用账号 | U004 登录返回 401 `ACCOUNT_DISABLED` |
| 角色隔离 | 检验人员访问系统设置、备份、账号、审计、任务重试均为 403 |
| 记录归属 | U001 修改 U002 记录返回 403 |
| 审计防篡改 | 自动化测试确认直接 UPDATE/DELETE `audit_logs` 被触发器拒绝 |
| SQL 注入 | 查询均使用参数绑定；用户输入未拼接进 SQL |
| 路径穿越 | 上传文件名经 `basename` 并使用随机文件名；截图名经白名单正则；静态文件根目录做 resolve 校验 |
| 上传偏移 | 服务端校验 `Upload-Offset` 与数据库偏移一致，并阻止同一会话并发写入 |
| 安全响应头 | 静态页面返回 CSP、nosniff、DENY frame、no-referrer 等头 |
| 错误信息 | 500 响应不返回堆栈 |

## 自动化验证

执行：

```powershell
cd tianping-system
node --test --test-concurrency=1
```

结果：26 项测试全部通过，包括真实样例 API 全流程、三段样例的确定性判定、
PDF 中文字体、CSV 编码、审计防篡改和备份完整性。

现有测试缺口：

- 未覆盖连续 5 次错误口令及锁定到期。
- 未验证缺少/错误 CSRF 头的所有变更端点。
- 未系统验证跨用户、跨角色、跨记录越权矩阵。
- 未覆盖上传会话上限、过期清理和磁盘不足。
- 未覆盖 CSV 公式注入。
- 未覆盖查询审计缺失和非原子审计故障。

## 建议修复顺序

1. 移除已知默认口令，并加入新库安全初始化约束。
2. 增加上传硬配额、TTL 清理和清理时排除分析中任务。
3. 来源 IP 改为可信代理策略。
4. 补齐查询审计，并将业务变更与审计写入事务化。
5. 修复 CSV 公式注入、路径 DTO 泄露和文本长度限制。
6. 补齐流错误、极端数值和队列崩溃恢复；新增上述回归测试。

本报告未修改任何业务文件；所有临时数据库和探针文件均已清理。
