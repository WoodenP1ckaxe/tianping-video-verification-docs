# Windows 安装包首次口令显示修复

日期：2026-11-23

## 现象

覆盖安装并打开控制面板后，持续显示：

```text
首次启动后将生成一次性口令，请稍候...
```

安装数据目录只有 `logs`，没有 `settings.ini`、数据库或
`initial-password.txt`；同时 8080 被另一个从源码目录启动的 Node 服务占用。

## 根因

1. 控制面板只根据 `/healthz` 的通用服务标识判断“本系统已运行”，把源码目录中
   另一个同品牌实例误认为安装包服务，因此跳过了安装包自己的 Node 启动流程。
2. 控制面板发布口令时先判断 `tianping.db` 是否存在。安装包服务正常启动后会立即
   创建数据库，这会使刚生成的初始口令被“系统已完成初始化”分支遮蔽。
3. Windows 允许外部实例监听 `0.0.0.0:8080` 时，安装包 Node 再监听
   `127.0.0.1:8080`，出现两个服务共用同一端口。

## 修复

- `FindRunningPort()` 只有在安装数据目录中存在有效 PID，且 PID 对应安装包内置
  `runtime\node.exe` 时才认定为本系统服务。
- 增加系统监听表检查；端口只要被任一地址监听，就选择下一个可用端口。
- 首次启动优先读取并显示仍存在的 `initial-password.txt`；只有口令文件不存在且
  数据库存在时，才显示“系统已完成初始化”。
- 新增静态回归，锁定 PID 校验、全地址端口检测和口令显示优先级。

## 实机复验

保留原源码服务占用 `0.0.0.0:8080` 的真实条件，覆盖安装修复后的包：

- 安装包服务自动选择 `127.0.0.1:18080`
- `/healthz`：HTTP 200
- 数据目录生成 `tianping.db`
- 数据目录生成 `initial-password.txt`
- Windows UI Automation 读取首次运行面板：`INITIAL_PASSWORD_VISIBLE`
- 未在日志或报告中输出口令原文
