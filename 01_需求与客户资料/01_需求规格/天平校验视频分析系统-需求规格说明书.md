## 2 系统定义

### 2.1 项目背景与现状问题

实验室要求电子天平每天使用前进行外部校验：使用 3 个标准砝码（例如 200g、50g、10g），每个砝码称重 3 次，共 9 次称量，每次示值均须落在标称值的 (1±0.05%) 范围内，当天方可使用该天平。当前作业与记录方式存在以下问题：

1. **工作量大且易出错**：每日需校验的天平超过 20 台时，检验员测试与记录工作量激增；同一检验员两次执行同类校验可能间隔约 3 个月，期间易遗忘操作细节、误填记录。
2. **信息孤岛**：不同品牌/规格的天平采用不同的打印、上传与留存方式，新购设备常存在通讯协议差异，历史数据无法统一检索。
3. **纸质记录难以回溯与纠错**：纸质记录累积后要么无法回溯检查，要么发现错误时已无法有效纠正。

### 2.2 系统目标

本系统以"固定支架手机拍摄的校验过程视频"为唯一原始证据来源，通过自动分析与自动判定，把一次天平日常校验转化为可查询、可复核、可导出的电子记录。具体目标：

1. 检验员只需拍摄视频并上传，系统自动识别人员、设备、9 次称重示值与读数时间，自动判定"通过/不通过"，大幅降低人工记录工作量。
2. 不同品牌、不同显示方式（七段码 LCD、彩色触摸屏）、单量程/双量程天平纳入同一套记录与检索体系，消除信息孤岛。
3. 满足"可操作、可重复、可溯源、可回溯"要求：视频为证，识别截图、读数时间、修改痕迹、审计日志与电子签名共同构成追溯链。
4. 在客户内网离线环境、Windows 与 Linux 双平台、无显卡的低配服务器上稳定运行。

### 2.3 系统角色与职责

| 角色 | 数量（初始） | 主要职责 | 关键权限 |
| --- | --- | --- | --- |
| 管理员 | 1 人 | 系统管理与运维配置 | 账号新增/停用/删除与角色分配、口令重置、天平档案与砝码盒字典维护、模板参数维护、分析队列查看与重试、存储容量配置、记录作废、审计日志查询与导出、系统运行状态查看 |
| 检验人员 | 2 人（李一、李二） | 现场拍摄、上传视频、核对并一键提交记录 | 上传视频、查看本人分析任务与全部记录、提交前修正字段与填写备注、提交后（复核前）修改备注、查看历史记录、导出（按权限见 4.1） |
| 复核确认人员 | 1 人（齐一） | 复核确认、模板与主数据维护 | 查看待复核记录、确认（电子签名）或退回、查看全部记录、导出 PDF、维护天平档案/砝码盒字典/记录模板参数 |
| 系统（自动） | — | 自动分析与自动判定 | 视频排队与串行分析、卡片与示值识别、读数时间还原、自动判定、生成记录草稿、容量监控与自动清理、审计记录写入 |

### 2.4 端到端业务流程

| 步骤 | 执行者 | 动作 | 输出 |
| --- | --- | --- | --- |
| 1 | 客户方 | 在天平上固定设备二维码卡，检验人员随身携带人员二维码卡 | 可识别的二维码卡 |
| 2 | 检验人员 | 使用固定支架拍摄：开机后先依次清晰展示人员卡与设备卡，随后按要求完成 9 次称重；双量程天平在高量程完成 3 次称重后切换量程，再完成 6 次称重；过程中口述"第一次""第二次"…等关键词 | 校验过程视频 |
| 3 | 检验人员 | 通过 PC 浏览器或手机浏览器登录系统并上传视频（必要时确认拍摄开始时间） | 分析任务（排队中） |
| 4 | 系统 | 按上传顺序串行分析视频：识别卡片、切分 9 次称重、识别示值与单位、还原每次读数时间 | 记录草稿与判定结论 |
| 5 | 检验人员 | 查看记录总览（低置信字段高亮），必要时修正字段、填写备注、输入本次使用的砝码盒编号，然后一键提交 | 已提交记录（电子确认） |
| 6 | 复核确认人员 | 查看视频、识别截图与判定依据，确认（电子签名）；发现问题时退回并（可选）填写理由，或按现有方式口头通知检验人员修改 | 已复核确认记录 / 退回记录 |
| 7 | 检验人员 / 复核确认人员 | 查询记录、按需导出单条或批量 PDF、导出周统计表并打印留档 | PDF 记录、纸质留档 |

### 2.5 系统边界

视频上传与存储、自动分析、自动判定、记录生成与流转、查询与统计汇总、导出与打印、模板参数配置、账号与权限、主数据管理、审计与系统管理。

### 2.6 与现有记录方式的关系

1. 系统生成的电子记录与现有纸质《电子天平日常校验记录表》并行存在，纸质记录可继续打印留档（打印版式对齐现有记录表）。
2. 原流程中"打印纸贴附手写记录""上传 LIMS 后人工赋名"等方式继续由客户按现行制度执行，本系统不做替代。
3. 视频为原始证据，系统保存的视频、识别截图与读数时间用于支撑电子记录的可追溯性。
4. 校验记录中"清洁""水平调节""内部校正是否通过"等由检验人员口述确认，系统通过语音关键词识别生成候选值，识别不确定时留空并标记"待核对"，由检验人员在提交前确认。

| 组件 | 职责 |
| --- | --- |
| Web 前端 | 登录、上传、任务与队列查看、记录核对与提交、复核确认、查询与统计汇总、导出、主数据与模板配置、审计与运行状态 |
| 应用服务 | 业务逻辑、权限控制、记录状态机、判定规则计算、导出与打印、审计写入 |

## 3 应用环境

### 3.1 部署形态与拓扑

- 系统采用 B/S 架构，浏览器访问，服务器端统一完成视频分析；不安装客户端程序。
- 单机容器化部署：Web 前端、应用服务、分析服务、数据库、文件存储运行在同一台内网服务器上，通过 Docker Compose 编排（使用同一编排文件即可在 Windows 与 Linux 上部署）。

| 环境项 | 要求 |
| --- | --- |
| 部署方式 | 单机 Docker Compose 编排；提供离线镜像包与一键部署脚本 |
| 访问方式 | 内网浏览器访问（PC 与手机同一套页面，手机端用于上传） |
| 外网依赖 | 无，全部组件与模型离线打包 |

### 3.2 服务器硬件配置

| 项目 | 最低配置 | 建议配置 | 说明 |
| --- | --- | --- | --- |
| CPU | 4 核 | 4 核及以上 | 不支持/不要求 GPU；分析服务持续占用宜不超过 2 核 |
| 内存 | 4GB | 8GB~16GB | 分析与数据库同机运行 |
| 系统盘 | 100GB | 100GB SSD | 操作系统、容器镜像与程序 |
| 数据盘 | 320GB | 500GB 及以上 | 视频配额默认 200GB，其余用于数据库、识别截图、导出文件与备份 |
| 显卡 | 不需要 | 不需要 | 全部识别在 CPU 上完成 |
| 网络 | 千兆内网 | 千兆内网 | 与客户端同内网互联 |

说明：服务器整体性能预期不高，因此分析采用串行队列方式，系统接受"上传后排队等待、当天完成"的处理节奏（见第 5 章）。

### 3.3 操作系统与容器环境

| 环境项 | 要求 |
| --- | --- |
| Windows 部署 | Windows 10/11 或 Windows Server 2022，需启用 WSL2 后端并安装 Docker Desktop 或 Docker Engine（Linux 容器模式） |
| Linux 部署 | Ubuntu 20.04 LTS 及以上（含 22.04/24.04）等主流 x86_64 发行版 |
| 容器 | Docker Engine 20.10 及以上 + Docker Compose v2 |
| 离线安装 | 提供包含全部镜像、依赖包与识别模型的离线安装包及部署脚本 |
| 时间同步 | 服务器需可访问内网 NTP 时间源；时间统一使用 Asia/Shanghai 时区 |

### 3.4 网络环境与离线要求

- 系统整体在内网运行，不提供外网访问入口，不上传任何数据至外部服务。
- 全部识别能力（二维码、语音关键词、示值光学识别）必须使用本地离线模型，禁止调用在线 OCR/语音识别服务。
- 系统不得内置遥测、埋点上报等外发行为。
- 客户端与服务器需在同一内网；手机上传需可访问服务器内网地址。

### 3.5 客户端环境

| 客户端 | 要求 | 用途 |
| --- | --- | --- |
| PC 浏览器 | Chrome 或 Edge 最近两个大版本；分辨率不低于 1280×720 | 上传、提交、复核、查询、导出、配置、审计 |
| 手机浏览器 | iOS Safari 15+ 或 Android Chrome 100+ 及以上 | 上传视频（响应式页面，支持断点续传） |

### 3.6 存储与容量规划

| 项目 | 要求 |
| --- | --- |
| 视频存储配额 | 可配置，默认 200GB；达到 90% 时界面告警 |
| 配额达到上限 | 按"最早优先"自动清理最旧的视频文件，清理动作写入审计日志 |
| 清理影响范围 | 记录、判定结论、识别截图、PDF、审计日志不受清理影响 |
| 识别截图保留 | 长期保留（容量占用小），单个记录 9~18 张 |
| 记录与审计保留 | 电子记录与审计日志长期保留，默认不少于 5 年 |
| 参考容量 | 单段 5 分钟视频约 20~40MB；按每日 20 段估算，年增约 150~300GB，故需按配额滚动清理 |

### 3.7 时间与时区

- 系统统一使用 Asia/Shanghai 时区，服务器时间以 NTP 为准，界面与导出格式统一为 `YYYY-MM-DD HH:mm`。
- 校验日期取视频的拍摄开始日期；每次读数时间 = 拍摄开始时间 + 该次读数在视频中的时间偏移，精确到分钟。
- 视频元数据缺失（无拍摄时间）时，由上传者在界面确认拍摄开始时间（默认填入文件时间，必须人工确认后方可提交分析）。

### 3.8 备份与恢复

| 项目 | 要求 |
| --- | --- |
| 备份对象 | 数据库（账号、主数据、记录、读数、审计日志）、系统配置、模板版本 |
| 备份策略 | 每日自动备份一次（非工作时段），保留最近 30 天 |
| 视频备份 | 视频文件不纳入系统每日备份；原始视频存于数据盘并受 3.6 节配额策略管理，由客户运维按服务器现有备份策略决定是否另行备份 |
| 手动备份 | 提供管理员手动触发备份与查看备份状态的能力 |
| 恢复能力 | 提供恢复操作手册，并在验收阶段完成一次恢复演练 |

### 4.1 人员、角色与权限

| 编号 | 需求描述 | 优先级 | 客户复核 |

### 4.7 判定规则

| 编号 | 需求描述 | 优先级 | 客户复核 |
| --- | --- | --- | --- |
| FR-701 | 示值判定标准为 \|I − L\| ≤ 0.05% × L，边界值（恰好等于上下限）判为通过。 | 必须 | □同意 □需修改 |
| FR-702 | 每只砝码应各称重 3 次，单量程天平共 9 次读数；双量程天平同样共 9 次读数（高量程 3 次 + 低量程 6 次）。 | 必须 | □同意 □需修改 |
| FR-703 | 称重顺序应符合：L1 连续 3 次 → L2 连续 3 次 → L3 连续 3 次；双量程天平应先在高量程完成第 1 个标称点的 3 次称重，再切换量程完成剩余 2 个标称点的各 3 次称重。 | 必须 | □同意 □需修改 |
| FR-704 | 出现缺次、重复称重、顺序错误时，判定结论为"不通过"，并写明具体原因与位置。 | 必须 | □同意 □需修改 |
| FR-705 | 某次读数被判定为"不稳定"时，判定结论为"不通过（读数不稳定）"，并提示重新校验或核查该次称重。 | 必须 | □同意 □需修改 |
| FR-706 | 双量程天平未识别到量程切换过程段时，判定结论为"不通过（缺少量程切换）"。 | 必须 | □同意 □需修改 |

## 附录 C 判定算例

### C.1 判定式

对每只砝码的每一次称重：

- 标称值 L，读数 I；
- 下限 = L × (1 − 0.05%)，上限 = L × (1 + 0.05%)；
- 当且仅当 下限 ≤ I ≤ 上限 时，该次称重判为"在限内"（含端点）。

单条记录的判定结论：

```
记录通过 ⟺ 9 次读数全部"在限内"
          且 每只砝码各 3 次齐全
          且 顺序符合 L1×3 → L2×3 → L3×3
          且 双量程存在量程切换且读数归入正确量程
          且 9 次读数均为稳定读数
否则 记录不通过，并列出全部不满足项
```

### C.2 单量程天平（220g / 0.1mg）算例
