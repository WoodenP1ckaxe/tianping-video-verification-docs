# 天平校验视频分析系统交付计划

## 1. 目标与基线

以当前目录中的《天平校验视频分析系统 需求规格说明书 V0.9》、客户补充说明、
原始 Excel 记录表和 3 段样例视频为基线，交付一套可在内网运行的全栈应用。

交付目录为 `tianping-system/`，不得覆盖或改写现有需求文档、客户原需求目录和
`项目原型/`。

## 2. 交付原则

- 核心业务使用纯本地依赖，数据使用 SQLite 持久化，文件保存在可配置数据目录。
- Node.js 24 内建能力作为运行基线；浏览器端无 CDN、无远程字体、无遥测。
- 显示屏 OCR 使用本地七段码模板和离线 Tesseract 回退；ASR 通过清晰适配器接入。
  未识别出稳定示值时不得伪造结果，必须进入“待人工处理”或允许人工补录。
- 判定规则是独立、可复算的纯函数，任何界面和数据来源都不能绕过它。
- 所有关键业务动作必须同时写入审计日志；登录、CSRF、角色校验在服务端执行。
- 每个模块必须先满足 `tianping-system/ARCHITECTURE.md` 中的共享契约，再扩展细节。

## 3. 模块划分与责任

### M1 后端核心与持久化

- 账号、Role-Based Access Control、会话、首次改密、失败锁定。
- SQLite schema、初始化数据、事务与记录状态机。
- REST API、错误格式、审计日志、主数据与系统设置。
- 文件上传会话、断点续传、SHA-256 校验、容量统计。

产物：`server.js`、`src/db.js`、`src/auth.js`、`src/api.js`、
`src/services/uploads.js`、`src/services/storage.js`。

### M2 分析队列与判定

- FIFO 单消费者队列，服务重启恢复规则。
- FFprobe 媒体校验、逐秒显示屏 OCR、稳定段提取和人工补录通道。
- 稳定段、缺次、顺序、双量程切换和容差边界判定。
- 识别截图、置信度、失败码与任务追溯。

产物：`src/rules.js`、`src/services/queue.js`、
`src/services/analyzer.js`、`samples/manifests/`。

### M3 Web 前端

- 登录、工作台、视频上传/续传、任务列表。
- 记录核对、低置信修正、提交、复核、退回、作废。
- 查询、历史汇总、主数据、模板、账号、审计、运行状态。
- A4 打印版式、移动端响应式、统一错误提示。

产物：`public/index.html`、`public/assets/`。

### M4 导出、测试与运维

- 单条/批量 PDF、周统计 PDF、CSV 导出。
- 单元/接口/端到端冒烟测试和 26 条验收用例记录。
- Docker Compose、Windows/Linux 启停脚本、离线镜像制作说明。
- 用户手册、部署运维手册、数据库字典、恢复演练步骤。

产物：`src/services/exporter.js`、`tests/`、`docker*`、`scripts/`、`docs/`。

## 4. 共享接口冻结

所有模块以 `tianping-system/ARCHITECTURE.md` 为准。若实现需要变更字段，
必须由主代理先更新契约并通知受影响模块，禁止各模块私自定义同名字段。

## 5. 联调与验收顺序

1. 单元测试：判定边界、状态机、认证锁定、上传哈希。
2. 接口测试：登录 → 初始化上传 → 分片上传 → 队列完成 → 修正 → 提交 → 复核 → 导出。
3. 浏览器冒烟：三个角色、权限拦截、移动端上传、打印预览。
4. 样例视频：3 段视频映射为 2 通过、1 不通过，并保留可核对明细。
5. 部署演练：Windows 本机启动；Docker Compose 配置静态检查；备份恢复步骤核验。
6. 交付检查：无外网资源、无敏感数据、无占位“待实现”关键路径、文档与版本一致。

## 6. 明确的能力边界

当前交付实现完整的上传、队列、真实视频帧 OCR、人工核对、判定和追溯闭环，并提供
本地内置 ASR 适配器：`whisper.cpp` + 量化 `base` 模型 + Silero VAD、2 线程串行、
临时音频清理和稳定段编号冲突双提示。平台运行库、权重与许可证由构建流程校验后
自动内置到最终安装包和镜像，源码 Git 不提交大文件。正式上线前须在客户验收样本和
目标 4 核/4 GB 机器上完成字段级关键词
准确率、峰值内存和分析耗时实测；未达到阈值或低置信的字段进入人工核对流程。
